# ChronoGuard ｜ chronoguard-ts

**面向多通道时序数据的可复用异常检测流程与 Python 库。**

发行名 `chronoguard-ts`｜导入名 `chronoguard`｜版本 0.1.0

把无监督异常检测组织成一条**与具体物理量无关**的标准化流程：同一套接口与评估协议，
先在电池电压数据上成立，再原样搬到服务器监控数据上运行——中间只更换特征模式，不改检测内核。

**本仓库不主张新的检测算法。** 检测内核采用四种已发表方法（鲁棒绝对偏差、LOF、
Isolation Forest、PCA 重建残差），本作品只统一它们的输入契约、校准方式与评价协议。
整体范式属于基于正常参考的 novelty detection。

## 核心设计

**统一数据与输出契约。** 输入为三维有限数值数组 `(N, T, C)`（窗口数、窗口长度、通道数），
必须非空、三维且全部有限，NaN 与无穷被**显式拒绝**而非静默填补。通道语义由调用方声明，
库不自动识别单位、频率、时间戳或采样间隔——**相同形状不代表相同物理含义**。输出为结构化对象：
`scores`、`threshold`、`confirmed`、报警起止边沿、`channel_evidence` 及其排序，
以及可供下一连续块复用的 `state`。

**五阶段流程**（骨架固定，内核可替换）：

| 阶段 | 职责与约束 |
|---|---|
| ① 正常参考拟合 | 只用业务确认的正常参考估计中位数中心 + 1.4826×MAD 尺度；拟合侧按时间顺序均匀抽样，最多 6000 窗 |
| ② 独立校准 | 在**与拟合段不重叠**的独立正常段上计算分数分布，取 q99 作为阈值；阈值不随测试数据变化 |
| ③ 因果连续报警 | 严格 `score > threshold`；连续 5 窗超阈值才**从第 5 窗起**确认，不回填前 4 窗；一窗未超即解除 |
| ④ 通道证据排序 | 输出每通道标准化偏离量并排序，供人工核验线索——**不是**模型分数的归因分解 |
| ⑤ 严格逐点评价 | **不做 point adjustment**；FPR 分母为实际正常点；事件延迟只统计已检出事件 |

时序切分固定为按时间顺序的 **60% 拟合 / 20% 校准 / 20% 验证**，seed 42。

**两种特征模式**，把跨学科复用中最棘手的「通道之间能不能比较」交给使用学科显式声明：

| 模式 | 每通道统计量 | 使用边界 |
|---|---|---|
| `peer` | 相对通道中位数残差的均值、标准差、绝对残差 q95、残差差分标准差 | 要求 ≥2 个**物理可比较的同类通道**，不能混合电压、温度、转速等不同单位 |
| `independent` | 均值、标准差、极差、归一化时间轴上的线性斜率、差分标准差 | 适用于**量纲各异的异构通道**，不直接混合不同物理量 |

**因果性与防泄漏。** 先按时间切分拟合／校准／验证三段，再各自构造窗口；标准化参数只来自拟合侧；
标签只用于评价。`state` 绑定设备与模型／校准版本，重新拟合或校准后旧状态被拒绝，不能跨设备复用。

## 安装与运行

核心流程**不需要 PyTorch、CUDA、MATLAB 或 Office**，只依赖 NumPy、scikit-learn、joblib；
绘图为可选的 `[plot]` 依赖。已验证环境为 Python 3.12.14。

```bash
cd framework
python -m pip install -r requirements.txt
python -m pip install -e . --no-deps
python -X utf8 -B -m unittest discover -s tests -v
python -X utf8 -B examples/demo.py
```

## 实验与验证

两类学科场景共用同一套固定协议（q99 阈值、连续 5 窗确认、seed 42、最多 6000 拟合窗）：

| 数据域 | 规模 | 特征模式 |
|---|---|---|
| 电池（正常留出） | 4 个正常包共 **26508 窗** | `peer` |
| 服务器 SMD | 3 台机器共 **80873 个测试点** | `independent` |

- **28 组实验** = 16 组电池 + 12 组 SMD
- **120 项测试，0 失败** = 34 项新库单元测试 + 86 项原研究体系回归测试
- **SHA256 溯源**：49 个产物哈希与 12 个输入哈希已核对，12 组 SMD 指标从保存的逐点预测
  重新计算并与汇总一致；对第三方数据，下载清单存在时会核对来源、文件清单项与 SHA256，
  **不符或缺项即拒绝读取**

### 结果（完整陈述，不择优）

电池侧**只有正常留出评价**，下表为确认报警窗口比例的四包宏平均：

| robust | LOF | Isolation Forest | PCA |
|---:|---:|---:|---:|
| 0.087% | 6.914% | 0.005% | 0.580% |

这些数值**不能证明任何方法有较好的故障召回**：没有真实故障标签与独立事件记录，
无法计算真实故障的 Recall、F1、提前量或定位准确率。LOF 在包 8、包 10 出现明显跨包误报。

SMD 三机器的宏平均严格逐点 F1：

| robust | LOF | Isolation Forest | PCA |
|---:|---:|---:|---:|
| 0.2436 | 0.2379 | 0.1102 | 0.2486 |

效果有限，且机器间差异明显。machine-3-1 的 LOF 虽然命中 4/4 个事件，正常点 FPR 却达 28.219%、
严格 F1 仅 0.0384——**不能只宣传事件全命中**。此处按机器逐台报告，未挑选每台机器的最优方法
拼成「总体成绩」。

完整协议、逐机器表格与 MAD 退化修正前后的全部对照见
[benchmarks/20261008/REPORT.md](benchmarks/20261008/REPORT.md)。

## 局限（完整陈述）

- **检测效果有限，且尺度修正属开发复验。** MAD 退化修正发生在已查看同一测试数据结果之后，
  **不能称为一次全新未见测试集的盲验**。
- **电池侧没有真实故障标签**，只能报告正常参考上的确认报警率。
- **SMD 只有 3 台机器**，不代表完整 28 台；没有重复随机种子、置信区间或同协议先进方法对照，
  不能得出统计显著改善或 SOTA 结论。
- **窗口重叠未能独立核实。** 电池输入是已构造好的缓存窗口，缺少时间戳与步长，
  不能宣称已排除全部原始点级泄漏。SMD 训练段的正常性是参考假设，未经独立核实。
- **不承诺跨领域自动迁移。** 换场景需要正常参考数据、明确的通道语义、合适的特征模式，
  并**重新拟合与校准**。
- **不代表生产可用**，不支持现场上线或安全控制结论；通道证据不能代替因果解释或真实根因定位。
- **SHA256 只说明字节一致性**，不证明数据真实性、无泄漏或模型来源可信。

> **创新点定位（避免夸大）：** 本作品的创新性在**工程与评估层面**——把碎片化的场景代码提炼为
> 统一契约的库、区分同类／异构通道两种特征语义、把独立校准与因果连续报警固化为流程、
> 并坚持不做 point adjustment 的严格评价。本作品**不主张**新的检测算法，
> **不主张**对现有方法的改进，**不主张**跨领域自动迁移能力。
