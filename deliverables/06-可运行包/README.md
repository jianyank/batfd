# 可运行包（代码 + 数据在一起）

把**交付源码包**与**真实数据**放在同一目录下，用于验证提交物能否直接跑通。

```text
06-可运行包/
  run_all.sh                 一键端到端验证
  chronoguard_ts-0.1.0/      解压自 ../05-代码包/chronoguard_ts-0.1.0-source.zip
  datasets/                  目录联接 -> ../../../datasets（真实数据，未复制）
  _运行输出/                 运行产物（每次运行前自动清空）
```

**测的是要交的那个包**：这里的 `chronoguard_ts-0.1.0/` 是从交付 zip 解压出来的，
不是仓库工作区里的源码。

## 搭建方式

```bash
cd deliverables/06-可运行包

# 1. 解压交付源码包
python -c "import zipfile; zipfile.ZipFile('../05-代码包/chronoguard_ts-0.1.0-source.zip').extractall('.')"

# 2. 联接真实数据（不复制，省 2.7 GB）
cmd //c "mklink /J datasets D:\\Matlab\\project\\pypack\\datasets"
```

代码通过 `_repo_root()` 定位仓库根：它取脚本自身位置的上一级，若同级存在 `datasets/` 就用它，
否则回退到当前目录。因此只要 `datasets/` 与 `chronoguard_ts-0.1.0/` 同级，默认路径即可解析，
**无需传任何路径参数**。

## 运行

```bash
bash run_all.sh
# 若 python 不在默认位置：
PY=/path/to/python bash run_all.sh
```

脚本逐步执行 9 项，逐项报告通过或失败，最后给出汇总。

## 两点说明

1. **`datasets/` 是目录联接，不是副本。** 它指向仓库的 `datasets/`，
   **不会随文件夹一起复制到别的机器**。别人拿到这个目录需要自备数据；
   这也是本项目一贯的做法——数据不随交付物分发。

2. **`.gitignore` 已排除本目录下的 `datasets/`、`_运行输出/` 与解压出的源码副本。**
   原因：git 会**跟进目录联接**，若不排除，SMD 的 53 MB `.txt` 与各 `meta.json`
   会被加入版本库。改动 `.gitignore` 前请先确认这一点仍然成立。
