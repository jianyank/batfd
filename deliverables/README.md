**作品简介**（存于技术方案，此处仅作核对）

> 电池运维与服务器监控属不同学科，却面对同一类问题：无故障标签、通道语义异构，代码与单一场景深度耦合，换数据即需重写。本作品把电池电压研究代码提炼为可独立安装的 Python 算法库，用统一 (N,T,C) 契约连接「正常参考拟合 → 独立校准 → 因果连续报警 → 通道证据 → 严格逐点评价」五阶段流程，并用 peer / independent 两种特征模式适配不同学科的通道语义。库在两场景完成 40 组固定协议实验，配 120 项测试与 SHA256 溯源。工程封装与接口复用已完成，检测效果仍有限：服务器三机宏平均严格 F1 仅 0.11–0.29，电池只验证正常参考上的报警率。本作品不主张新算法，也不代表可直接用于安全控制。

## 5. 其他必须遵守的约束

1. **数据许可**：电池数据来自公开数据集（DOI `10.5281/zenodo.13715694`），许可 **CC-BY-NC-4.0**。必须署名并给出 DOI；**含 NC 条款，不得用于商业化场景或创新创业类赛道**。服务器数据来自 OmniAnomaly（MIT）。
2. **引用标注**：引用他人技术、算法、数据须明确标注。技术方案已逐条标注参考文献（7 条，均已核实）。
3. **不夸大效果**：本项目电池侧**没有真实故障召回率**，服务器侧严格 F1 仅 0.11–0.29。技术方案第 4.4 节已完整陈述 8 条局限，答辩时不要偏离该口径。
4. **不主张原创算法**：robust / LOF / Isolation Forest / PCA 均为既有方法，作品的贡献定位是**流程与评估协议的可复用性**。
