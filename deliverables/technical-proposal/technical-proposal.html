面向多通道时序数据的可复用异常检测流程

赛道：AI + 学科交叉
作品简介
电池运维与服务器监控属不同学科，却面对同一类问题：无故障标签、通道语义异构， 代码与单一场景深度耦合，换数据即需重写。本作品把电池电压研究代码提炼为可独立安装的 Python 算法库，用统一 (N,T,C) 契约连接 「正常参考拟合 → 独立校准 → 因果连续报警 → 通道证据 → 严格逐点评价」五阶段流程， 并用 peer / independent 两种特征模式适配不同学科的通道语义。库在两场景完成 40 组固定协议实验， 配 120 项测试与 SHA256 溯源。工程封装与接口复用已完成，检测效果仍有限： 服务器三机宏平均严格 F1 仅 0.11–0.29，电池只验证正常参考上的报警率。 本作品不主张新算法，也不代表可直接用于安全控制。
诚实声明（贯穿全文的写作原则）：本作品所要主张的是检测流程与评估协议的可复用性， 而不是一种新的检测算法。所用 robust、LOF、Isolation Forest、PCA 四种方法均为已发表的既有工作， 本作品不声称对其作出原创性改进，也不声称已取得领先或生产可用的检测性能。全文所有实验数字 均来自本作品实际运行的固定协议实验，未作任何修饰或择优拼接。

1　需求分析

1.1　两个学科场景，同一类技术问题

本作品源于一个跨学科的现实观察：电池储能运维与服务器系统监控看似属于材料／电气与计算机两个 相距甚远的学科，但在"用无监督方法发现多通道时序数据中的异常"这一环节上，它们面临的技术约束几乎完全重合。

在电池场景中，一个电池包内 8 个串联单体是可相互比较的同类通道，单体电压之间的相对偏离蕴含单体级故障线索； 在服务器场景中，一台机器的 38 个监控通道（CPU、内存、磁盘、网络等）是量纲互不相同的异构通道。 两者的共同点是：（i）真实故障标签稀缺乃至不存在，监督学习不可用； （ii）正常参考数据相对易得，可用于刻画"正常应该长什么样"； （iii）告警必须满足因果性——不能用未来数据判断当前点是否异常，否则无法在线部署； （iv）在生产中误报成本高昂，"连续几窗确认后才报警"比"单点超阈值即报警"更可接受。

因此，两个学科场景真正需要的并不是"又一个检测模型"，而是一套与具体物理量、具体领域解耦、 可被不同学科直接复用的检测流程与评估协议。这正是本作品的出发点。

1.2　现有做法的三处断裂

在本作品开始整理前，团队原有的电池检测研究代码已经能够跑出结果，但其结构存在三处影响跨学科复用的断裂， 它们在跨领域迁移时逐一暴露：

断裂点问题表现对跨学科复用的影响
特征断裂 特征提取与"电压单体"这一具体物理量硬绑定，统计量、通道选取都写死在电池代码里。 换成服务器监控这类异构通道时无法直接使用，必须重写特征层，且容易把不同量纲的通道错误混合。
校准断裂 阈值、标准化参数来自同一个被观察的数据集，拟合、校准、评价边界不清，存在信息泄漏与事后调阈值的风险。 换领域后阈值失去意义；若沿用同一套阈值选择逻辑，会得到"看起来很好但不可复现"的结果。
评价断裂 评价采用逐点指标但常隐含 point adjustment——事件内命中一次就把整段补为检出，抬高指标。 不同学科、不同团队的结果无法横向比较，也无法判断迁移后到底是变好还是变差。

1.3　为什么需要"可复用流程"而不是"更复杂的模型"

一个自然的直觉是：既然检测效果有限，就应该上更深的模型（如深度自编码器、LSTM 预测残差等）。本作品没有 走这条路，理由有三点，且都有本次实验的证据支撑：

  • 数据规模不支持。本作品可用的电池正常参考共 26508 窗、服务器三机共 80873 个测试点， 且电池侧完全没有真实故障标签。在这种规模下训练深度模型，其增益无法被可靠地验证。
  • 评价协议的重要性不低于模型。第 4.2 节将展示：同一个 LOF 模型，仅仅因为评价协议是否做 point adjustment、以及时序窗口长度取 1 还是 16，就会呈现出从"三机宏平均 F1 0.2379"到 "0.1260"的巨大差异。这说明先统一协议，再谈模型是更有效的路径。
  • 复用的瓶颈在接口而非算法。第 4.3 节的尺度对照实验说明，跨场景失效往往来自特征与尺度的 不匹配，而这属于接口层的设计问题，不是换一个更强的算法就能解决的。

据此，本作品的定位确定为：把既有方法组织成一条标准化的、可校准、可复现、可严格评价的流程， 并把这套流程封装为可独立安装的库。

2　技术方案

2.1　统一数据与输出契约

跨学科复用的第一道关口是数据表示。本作品定义了一个与具体物理量无关的统一输入契约：

  • 输入为三维有限数值数组 (N, T, C)：N 为有序窗口数， T 为窗口长度，C 为通道数。输入必须非空、三维且全部有限； NaN 与无穷会被显式拒绝，不做静默填补。拟合至少 3 窗、校准至少 2 窗（这是 API 下限，不是 统计充分性的保证）。
  • 通道语义由调用方声明。库不自动识别单位、频率、时间戳或采样间隔；通道顺序或窗口长度改变时必须 重新拟合与校准——相同形状不代表相同物理含义。
  • 输出为结构化对象：异常分数 scores、阈值 threshold、 超阈值标记 exceeded 与连续确认标记 confirmed、 报警起止边沿 alarm_started / alarm_cleared、 通道证据 channel_evidence 及其排序 ranked_channels， 以及可供下一连续块复用的状态 state。

契约中刻意保留了两条"拒绝服务"的设计：其一，一个 predict 调用只能对应 同一设备的一段连续有序序列，库不检查时间戳，连续性须由调用方保证；其二，state 绑定设备与模型／校准版本，重新拟合或校准后旧状态会被拒绝，不能跨设备复用。这两条设计把"边界正确性"的责任 明确划给调用方，避免了跨学科场景中最常见的隐性错误。

2.2　五阶段流程

在统一契约之上，本作品把检测组织为五个明确分离的阶段，每个阶段的职责与可见信息都被严格限定。 其中检测内核采用四种既有方法——鲁棒绝对偏差、LOF[1]、Isolation Forest[5] 与 PCA 重建残差；本作品不修改其算法本身，只统一其输入契约、校准方式与评价协议。整体范式属于 基于正常参考的 novelty detection[2]。

阶段名称职责与约束
①正常参考拟合 仅用业务确认的正常参考数据估计标准化参数（中位数中心 + 1.4826×MAD 尺度）与模型内部结构。 拟合侧按时间顺序均匀抽样，最多 6000 窗。
②独立校准 在与拟合段不重叠的独立正常校准段上计算分数分布，取 q99 作为阈值。 修正后阈值不随测试数据变化。
③因果连续报警 严格 score > threshold；连续 5 窗超阈值才从第 5 窗起确认， 不回填前 4 窗。一窗未超阈值即解除。
④通道证据排序 输出每个通道的标准化偏离量并排序，用于人工核验线索，不是模型分数的归因分解。
⑤严格逐点评价 逐点指标不做 point adjustment；FPR 分母为实际正常点；事件延迟只统计已检出事件。

时序切分固定为按时间顺序的 60% 拟合 / 20% 校准 / 20% 验证，随机种子 seed 42。这五阶段的分工， 是本作品"方案可行性"的直接来源：任何一步出错都能被单独定位（第 4.3 节的尺度实验正是借这套分工才找到根因）。

图 1　流程实例：本图展示的是上述五阶段流程在电池场景上的一个具体实例（256×20 输入 → 32 维单体相对中位数残差 → 中位数 / MAD 标准化 → LOF 新样本评分 → 连续 5 窗确认）， 并非通用流程图。换到服务器场景时，特征模式、维度与所用方法均可替换，而五阶段骨架保持不变。

2.3　两种特征模式：面向学科语义的适配层

跨学科复用最实际的困难在于"通道之间能不能比较"。本作品没有回避这一点，而是显式提供两种特征模式， 把选择权交给使用学科：

特征模式每通道统计量使用边界
independent 均值、标准差、极差、归一化时间轴上的线性斜率、差分标准差 不直接混合不同通道的物理量，适用于异构监控通道；仍需每通道正常参考标准化。
peer 相对通道中位数残差的均值、标准差、绝对残差 q95、残差差分标准差 要求至少 2 个物理可比较的同类通道，不能混合电压、温度、转速等不同单位。

这一区分直接对应两个学科场景：电池的 8 个串联单体电压彼此可比，用 peer， 其核心统计量是"某单体相对全部单体中位数的残差"；服务器的 38 个通道量纲各异，用 independent， 逐通道独立统计。正是这条适配层，使同一套代码得以在两类数据上运行，而不需要改写检测内核。

标准化一律采用中位数中心 + 1.4826×MAD 尺度，而非均值／标准差，理由来自对异常敏感的鲁棒统计实践[3]。 针对稀疏变化特征（大部分时间不变、偶有变化）可能出现的零 MAD退化，本作品建立了显式的回退规则： 当 MAD < 1e-7 且拟合侧标准差 ≥ 1e-7 时，回退到拟合侧标准差；否则按 MAD 处理并设 1e-7 下限。 该规则的定位是已定位工程缺陷的修正，不是原创算法（见 4.4 节第 4 条与第 8 条）。

2.4　因果性与防泄漏

在线检测的可用性取决于两点：不用未来信息，且不把评价信息回流到建模。本作品的处理是：

  • 先划分角色，再构造窗口。原始序列先按时间顺序切为拟合／校准／验证三段，再各自构造窗口， 避免拟合窗口与校准窗口跨边界共享原始采样点。窗口只含末端及其之前的数据。
  • 标准化参数只来自拟合侧。中心、MAD 与退化回退标准差全部只在拟合段计算；校准与测试段 不会更新它们。
  • 标签只用于评价。测试标签不进入模型拟合、阈值校准或参数选择。
  • 分块一致性。同一连续序列分块预测时原样传递状态，其报警结果与整段一致；换设备或独立序列 必须显式重置状态，否则边界附近的连续确认会改变。
必须同时声明的边界：电池输入是已构造好的缓存窗口，缓存没有时间戳与步长， 因此本作品无法独立核实相邻窗口是否在原始采样层重叠，不能宣称已排除全部原始点级泄漏。 另外，当 T = 16 时独立测试段前 15 个点是预热区，不产生输出，评价必须明确这一覆盖范围， 不得把预热区补为正常预测后混入指标。

2.5　严格评价：为什么不做 point adjustment

时序异常检测领域长期存在一个被广泛批评的评价惯例——point adjustment，即只要一个异常事件内有一个点被正确 命中，就把该事件内所有点都替换为命中。这会系统性地高估模型能力[4]。本作品明确拒绝该惯例：

  • 逐点指标直接使用 confirmed 标记计算，一次命中不会把整个事件补为检出。
  • FPR 的分母是实际正常点；只有正常数据可用时，只能报告正常报警率， 不能评价真实故障的 Recall / F1。
  • 事件延迟只统计已检出事件，从事件开始到首次确认的采样点偏移，未检出事件不计"零延迟"。

这套协议是跨学科结果可比较的前提，也是本作品"方案可行性"得分的核心依据之一：任何人用同一套协议复跑， 都能得到可比对的数字。

2.6　设计原则：不追求跨领域自动迁移

本方案最重要的设计原则是克制——明确不承诺"跨领域自动迁移"，因为这种承诺在无监督异常检测中不可兑现。 换一个场景，本作品要求使用者显式提供：正常参考数据、明确的通道语义、合适的特征模式，并重新拟合与校准。 这不是缺陷，而是对本类问题数据本质的尊重。

创新点定位（避免夸大）：本作品的创新性在于工程与评估层面——把碎片化的场景代码提炼为 统一契约的库、区分同类／异构通道两种特征语义、把独立校准与因果连续报警固化为流程、 并坚持不做 point adjustment 的严格评价。本作品不主张新的检测算法，不主张现有方法的改进， 不主张跨领域自动迁移能力。

3　项目实施

3.1　交付形态：可独立安装的库

为让流程真正可被他人复用，本作品没有停留在"研究脚本"，而是交付一个可独立安装的 Python 包： 发行名 chronoguard-ts，导入名 chronoguard，版本 0.1.0。 交付物为 wheel 与源码包（sdist）两种形态，均不含私有数据、下载数据、模型、逐点预测、Git 历史、缓存或日志。

  • 核心库共 393 行、5 个模块，分别为 detector.py（拟合、校准、因果预测、分块状态、模型持久化）、 features.py（两种特征模式与通道适配）、 data.py（因果构窗、角色切分、外部数据读取与校验）、 evaluation.py（严格逐点指标、报警区间、正常序列报警率）、 __init__.py。
  • 零重依赖：核心流程不需要 PyTorch、CUDA、MATLAB 或 Office；仅依赖 NumPy、scikit-learn、joblib， 实验间接使用 SciPy 与 threadpoolctl，绘图为可选的 [plot] 依赖。 这使得库可以部署在没有 GPU 的普通环境。
  • 已验证环境为 Python 3.12.14、NumPy 2.5.2、SciPy 1.18.1、scikit-learn 1.9.1、joblib 1.6.0、 threadpoolctl 3.7.0、matplotlib 3.11.2。

3.4　哈希溯源

为让结果可被独立核对，本作品对源码、输入数据、模型、产物四类对象建立了完整的 SHA256 溯源： 本次共核对 49 个产物哈希与 12 个输入哈希，12 组 SMD 指标从保存的逐点预测重新计算并与汇总一致。 provenance.json 保存固定协议、版本与源码／输入 SHA256。 对第三方服务器数据，库在下载清单存在时会核对来源、三类文件清单项与 SHA256，不符或缺项即拒绝读取。

溯源的边界：SHA256 只说明字节一致性，不证明数据真实性、无泄漏或模型来源可信。 哈希本身不能替代人工核验；攻击者可以同时替换对象与其哈希。

4.3　核心贡献：时序尺度对照实验与距离对比度机理

本节是本作品最具方法论价值的部分，也是"方案可行性"评分项的核心证据。它回答了一个跨学科复用中 至关重要的实际问题：把同一套流程迁移到另一个场景时，方法为什么会失效？

本作品设计了严格的对照实验：同一份数据、同一套代码、同一套协议（q99 / 连续 5 窗 / seed 42 / 最多 6000 拟合窗）， 唯一改变的是窗口长度 T（T=1 的逐点基线与 T=16 的开窗），从而把"时序尺度"这一变量的影响单独隔离出来。

机理：距离对比度的塌缩。实验给出的特征空间诊断揭示了根因。在 machine-3-1 的校准集 800 点子样本上 计算特征空间点对距离的变异系数（CV）与 p95/p5 对比度：

尺度有效特征维度点对距离 CVp95 / p5 对比度
T = 1303.45565.8×
T = 161500.4043.1×

随着窗口长度增大，有效特征维度从 30 升到 150，数据在特征空间中越来越"拥挤"， 点与点之间的相对距离差异被压缩（p95/p5 对比度从 65.8× 塌缩到 3.1×，CV 从 3.455 降到 0.404）。 此时 "邻居明显近于非邻居"这一前提不再成立，而 LOF 的局部可达密度恰恰建立在该前提之上[1]， 于是 LOF 的判别力被直接削弱；robust、PCA、Isolation Forest 不依赖邻居对比，未出现同等退化。 这解释了为什么上表中只有 LOF 出现了 −0.1119 的显著下降。

效应还因机器而异：machine-1-1 的 LOF 宏 F1 从 0.4046 降到 0.1577（召回塌陷）， machine-2-1 从 0.2706 降到 0.1645，而 machine-3-1 反而从 0.0384 微升到 0.0558。 说明尺度效应与具体数据的维度／冗余结构有关，不能简化为"T 越大越差"的单一结论。

图 5（核心图）　三机器 × 两尺度（T=1 左 / T=16 右）的 LOF 分数并排对比，含阈值与真实异常区间。 左列为逐点基线；右列为 T=16 开窗。注意 T=16 的分数曲线整体被压平、与阈值的区分度下降， 与上文"距离对比度塌缩"的机理一致。

这一实验的价值不限于解释 LOF：它给出了一条可迁移的复用诊断方法——在把流程迁移到新场景前， 先测量特征空间的成对距离对比度，即可预判哪种方法可能失效。这正是本作品把"评估流程"与"检测流程" 并列为核心交付的实证理由。

4.4　局限与边界（完整陈述）

以下 8 条局限是本作品不可回避的边界。完整陈述它们，而非淡化，既是本作品一贯的风格，也是方案可行性的一部分。

  1. 检测效果有限。SMD 三机宏平均严格 F1 仅为 0.11–0.29；电池场景只有正常参考上的报警率， 没有真实故障召回率。
  2. 电池"训练数据无故障"的前提未获证实，且现有证据对它不利。所依据的公开数据集官方 README 声明全部 28 个系统均因"不满意行为"退回厂家。因此不能假定留出包 6/8/9/10 是无故障的正常参考，包 8 的 18.453% 不能表述为"误报"，应表述为"未解释的跨包报警"。
  3. SMD 只覆盖 3 台机器（数据集共 28 台）；且 T=1 时除均值外的时序统计量为零， 本作品在 SMD 上是明确的逐点基线，不代表已具备复杂时序建模能力。
  4. 尺度修正发生在已查看同一测试集结果之后，属开发复验而非全新盲验；结果不能包装为"未见测试集验证"。
  5. 电池缓存无时间戳，无法独立核实相邻窗口是否共享原始采样点，不能宣称已排除全部原始点级泄漏。
  6. 通道证据是辅助偏离量，不是 LOF / Isolation Forest 分数的归因分解，也不等于故障根因定位或 真实单体定位准确率。
  7. 许可约束：所依据的电池现场数据集为 CC-BY-NC-4.0，含 NC（非商业）条款。 用于本次校园算法竞赛（AI+学科交叉）属非商业用途；不得用于商业化场景或创新创业类赛道。 引用须署名并给出 DOI。
  8. 本作品解决的是流程复用问题，不主张新的检测算法；MAD 退化的回退规则是已定位工程缺陷的修正， 应表述为工程修正，而非原创检测方法。

5　总结与展望

5.1　总结

本作品围绕"让异常检测流程能跨学科复用"这一目标，完成了三项具体工作：

  • 把碎片化的场景代码提炼为标准化流程与可安装库。定义统一 (N,T,C) 输入契约与结构化输出契约，固化"正常参考拟合 → 独立校准 → 因果连续报警 → 通道证据 → 严格逐点评价" 五阶段，并以 393 行核心代码、5 个模块交付，无 GPU／MATLAB 依赖。
  • 用两个学科场景验证了流程的可用性。电池（4 包 26508 窗）与服务器监控（3 机 80873 点） 在同一套接口与协议下完成 40 组实验，配 120 项测试与完整 SHA256 溯源。
  • 给出了迁移失效的可诊断机理。通过只改变窗口长度的严格对照实验，定位到"特征空间点对距离对比度塌缩" 这一根因，并说明为何依赖邻居对比的 LOF 会退化，而其余方法不会。

同时，本作品对自身的边界做了诚实陈述：检测效果有限、电池侧缺少真实故障标签、"训练数据无故障"的前提未获证实、 尺度修正属开发复验、数据许可限制商业用途。本作品交付的是可运行、可复用、可检查的技术基础， 不代表已经满足全部生产条件，也不主张领先性能。

5.2　展望

下一阶段的工作方向明确且可执行：

  • 取得事件级真值。这是最有价值的一步：一旦获得电池包的故障事件记录与可信时间映射， 即可在本作品现成的严格评价协议上直接计算真实故障召回率、提前量、事件延迟与单体定位准确率—— 流程不需要改动，只缺标签。在此之前，任何"召回率"表述都是不成立的。
  • 扩展到完整数据域。SMD 从 3 台扩展到全部 28 台；电池测试缓存已具备 14 包、69216 窗的规模， 可在冻结模型后做逐包评价。
  • 设计真正独立的盲验。冻结源码与阈值后，在新的、此前未查看的数据域上评价，以替代当前的开发复验， 并在多随机种子下给出置信区间。
  • 把对比度诊断产品化。将 4.3 节的距离对比度测量做成迁移前的预检步骤，使其成为复用流程的标准一环。
  • 在合规前提下扩展学科。本作品的特征模式与评价协议与具体物理量无关，具备扩展到 工业设备、环境监测等其他多通道时序场景的接口基础；但每一次扩展都需要新的正常参考数据与重新校准， 本作品不承诺自动迁移。
