# 参赛作品说明：ChronoGuard

建议题目：**面向多通道时序数据的校准式异常检测与可复现评估算法库**
日期：2026-10-08｜版本：0.1.0

## 一句话介绍

将原电池异常检测项目提炼为独立可安装的 Python 库，用统一接口连接特征、正常参考拟合、独立校准、连续报警、通道证据和严格评价，在电池及服务器监控两个场景中验证工程可复用性。

## 作品定位

- 是“接口与评估流程可复用”，不是一个冻结模型跨领域通用。换场景需要正常数据、明确通道语义、合适特征及重新拟合/校准。
- 无界面、不堆深度模型；当前只有 robust / LOF / Isolation Forest / PCA 四种既有方法。
- 不把现有算法组合包装为原创新算法，也不声称已达到最先进效果。
- 可作为用户所述算法创新赛道的候选作品材料；本说明没有核实主办方当届规则，不能代替报名资格、原创性或交付要求确认。

## 已完成的工作

- 可安装的 chronoguard-ts 0.1.0，独立导入 chronoguard。
- 统一 (N,T,C) 输入，independent 与 peer 两种特征。
- fit / calibrate / predict 分离；正常校准 q99，连续 5 窗确认，seed42。
- 设备/模型/校准版本绑定的显式分块状态；断点重置与整段一致性测试。
- 通道证据、0 基排序、报警边沿、模型保存及可信加载边界。
- 34 项新库测试和原研究 86 项回归测试；wheel 与源码包独立安装验收。
- 4 个正常电池包共 26508 窗，3 台 SMD 服务器共 80873 个测试点；共 28 组实验。
- 源码快照、数据/模型 SHA256、严格逐点指标和完整局限说明。

## 可以主张的工程贡献，以及不能夸大的部分

| 可展示的工作 | 边界 |
|---|---|
| 独立算法库与统一数据/输出契约 | 尚未验证任意传感器、任意领域的有效性 |
| 同类通道 peer 与异构通道 independent 的明确区分 | 不自动识别物理单位或完成自动迁移 |
| 独立校准和因果连续报警 | q99 不保证部署域 1% 误报，连续窗不等于固定时间 |
| 显式状态、重拟合/校准失效检查、分块一致性 | 时间戳和采样断点须由使用方提供正确语义 |
| 稀疏变化特征的 MAD 退化诊断与拟合侧标准差回退 | 是已定位工程问题的修正，不应称为原创检测算法 |
| 不做 point adjustment 的公开评价与溯源 | 同一测试集已用于开发观察，修正结果不是盲验 |

## 效果必须完整陈述

电池仅有正常留出评价。确认报警率宏平均为 robust 0.087%、LOF 6.914%、Isolation Forest 0.005%、PCA 0.580%；这些数值不能证明任何方法有较好的故障召回。

SMD 三机器宏平均严格逐点 F1 为 robust 0.2436、LOF 0.2379、Isolation Forest 0.1102、PCA 0.2486。效果有限且存在明显机器差异；不能挑选每台机器的测试最优方法拼成一个“总体算法成绩”。
machine-3-1 的 LOF 虽命中 4/4 个事件，正常点 FPR 却为 28.219%，严格 F1 仅 0.0384，不能只宣传事件全命中。

详细表格、协议及尺度修正前后全部结果见 [实验报告](../benchmarks/20261008/REPORT.md)。

## 建议答辩演示顺序

1. 说明实际问题：原电池脚本为什么难以在异构监控数据上直接复用。
2. 展示 (N,T,C) 契约、两种特征与 fit → calibrate → predict。
3. 运行 examples/demo.py，明确这是人工注入演示，不是真实检测效果。
4. 展示整段/分块一致、跨设备错误状态拒绝、保存加载及测试记录。
5. 展示电池误报表和 SMD 严格逐点表，同时报告误报、未检出与局限。
6. 说明 MAD 退化根因、拟合侧回退及“开发复验”的事实。
7. 展示安装包、源码包、可复用接口及输入/源码哈希。

## 不应使用的表述

- “跨领域万能模型”“即插即用，无须重新训练”。
- “自主原创 LOF / Isolation Forest / PCA”。
- “实现可靠根因定位”“电池真实故障召回率已验证”。
- “q99 保证误报率 1%”“SMD 全数据集验证”“测试完全盲验”。
- “达到 SOTA”“可以直接用于生产安全控制”。
