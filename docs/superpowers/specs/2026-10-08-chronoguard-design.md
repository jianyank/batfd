# 多通道时序异常检测算法库设计

日期：2026-10-08｜状态：按已确认方向实现并进行交付验收

## 用户确认的范围

将现有电池项目提炼为 Python 算法库 ChronoGuard，服务于用户所述算法创新赛道。做可复用接口和严谨评价，不做界面、不堆算法、不把既有算法改名为原创，不承诺跨领域万能模型。

## 最小架构

- src/chronoguard/features.py：有限 (N,T,C) 输入校验、independent/peer 特征及电池通道适配。
- src/chronoguard/detector.py：robust、LOF、Isolation Forest、PCA；fit → calibrate → predict；显式分块状态、通道证据、保存/可信加载。
- src/chronoguard/data.py：因果构窗、按顺序60/20/20划分、SMD显式下载/加载与字节哈希。
- src/chronoguard/evaluation.py：严格逐点与事件指标、半开报警区间；不做point adjustment。
- tests/：接口、边界、原电池特征等价与回归测试；examples/：人工接口演示和固定协议实验。
- docs/：使用与参赛说明；benchmarks/：公开汇总和溯源；pyproject.toml：可安装发行包。

## 关键决策及原因

1. 不同设备/场景重新拟合正常参考，因为同一通道形状不代表相同分布或物理含义。
2. 异构通道使用independent；可比较同类通道才使用peer，避免直接混合物理单位。
3. 拟合与校准分离，测试不择阈值；q99和连续5窗是固定评估设置，不是部署保证。
4. 状态由调用方显式携带，绑定设备/模型/校准版本，避免跨设备或跨断点累计报警。
5. 统一通道证据但不冒充LOF/IF的分数归因；解释边界写入输出说明。
6. 模型加载限定可信joblib；哈希只核字节，不作为安全授权。
7. 不改变原用户研究文件和结果；新增库运行不依赖原研究脚本。

## 验收标准

四方法、有限输入与变通道契约；批量/分块一致；34项新测试及86项原回归；wheel和源码包独立安装；两场景28组固定实验；输入/源码/结果溯源；中文文档UTF-8无损；8份用户修改不变。

## 明确局限

电池只有正常留出误报；SMD只测3台，T=1为逐点基线。稀疏MAD修正发生在观察同一测试结果之后，只能称开发复验。缓存缺少原始时间戳/步长，不能独立排除训练/校准窗原始采样点重叠。效果有限，不得宣称盲验、领先、原创检测算法或生产安全可用。
