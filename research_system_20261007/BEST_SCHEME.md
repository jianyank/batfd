# 当前最佳研发方案与结果

## 方案

**LOF-Peer（lof_peer）**：输入校验 → 32维同伴残差 → 拟合域中位数/MAD标准化 → novelty LOF → 校准q99 → 连续5窗确认 → 单体证据Top-3。

- 历史冻结候选：final_candidate_v2；阈值：**2.02368862186493**。旧模型已归档、不随源码发布，新实验重拟合后阈值需重新校准。
- 依据：第二轮15种原始输入方法、四包探索性留出比较中，合成开发域综合效用最高；不代表真实故障性能最佳或统计显著胜出。

## 关键结果

| 合成开发域指标（四折宏平均） | LOF-Peer |
|---|---:|
| 存在点对点新增确认的注入事件比例 | 66.7% |
| 每折最差注入形态的上述比例，再取宏平均 | 43.8% |
| 全注入事件Top-1目标命中比例 | 61.8% |
| 参考片段已有报警比例 | 12.5% |
| 综合效用U | 0.5622 |

新增确认指注入后确认、而同位置参考未确认；Top-1包含未检出事件的事后最强证据排序。**以上不是真实检出率或在线定位准确率；参考片段来自无故障训练数据，其报警反映正常数据误报。**

- 固定96窗烟雾测试：参考0确认窗；合成偏移19确认窗、3个报警段；分段与整段重放一致。仅验证接口和该次注入响应。
- 历史工程验证：85项测试通过；当时研究产物与封存日志完成核验。当前源码的测试入口和验证结果见仓库根目录 `README.md`。

## 限制与结论

- 训练数据保证无故障；正常留出包6/8/9/10的确认报警窗比例为1.34%/20.38%/0.12%/16.30%，应作为正常数据误报表现，不据此宣称真实故障检出能力。
- TestData1有43个完整窗口与训练缓存逐值相同，不能整份视为独立盲验集。
- 真实近故障推理不需要故障标签；但真实检出、提前量与定位评价仍缺独立事件记录及可靠时间映射。物理字段和应用门槛未完全确认；初始异常、共同异常和缓漂移仍有风险。

**交付结论：推荐LOF-Peer作为可复现的离线研发主方案；真实效能未验证，deployment_approved=false。下一步应补齐独立验收证据，而非继续盲目堆叠算法。**
